# 00. Protocol, Snapshot Model, And Test Harness

## Goal

Define the cross-cutting protocol and test infrastructure before feature work
expands the automation surface. This plan owns versioning, capabilities, common
response shapes, snapshot/ref semantics, timeout budgeting, security gates,
artifact paths, and the native C++ MCP harness.

## Playwright Equivalent

This maps to Playwright's shared browser protocol behavior: stable action
responses, locator snapshots, trace/screenshot artifacts, versioned
capabilities, and deterministic test infrastructure.

## JUCE-Specific Differences

- The endpoint is a local JUCE `StreamingSocket` protocol, not a browser
  protocol.
- Snapshot refs are generated by melatonin_inspector and must not be treated as
  durable object ids.
- JUCE state can change without a browser-style navigation event, so snapshots
  need a semantic state hash in addition to a ref generation.
- MCP is served by the native C++ `melatonin-ui mcp` stdio mode. No Node or
  JavaScript adapter is part of the required implementation or test path.

## Public Protocol Changes

Add a `capabilities` method before adding more tools:

```json
{
  "protocolVersion": 1,
  "session": "automation_fixture",
  "features": {
    "locators": true,
    "actionability": false,
    "semanticControls": false,
    "richInput": false,
    "screenshots": true,
    "tracing": false,
    "windows": false
  },
  "security": {
    "allowInput": true,
    "allowMutation": true,
    "allowFileWrite": false
  }
}
```

Standard response envelope stays:

```json
{ "id": "1", "ok": true, "result": {} }
{ "id": "1", "ok": false, "error": { "code": "target_disabled", "message": "..." } }
```

Add stable fields to snapshot responses:

- `generation`: ref namespace only.
- `stateHash`: canonical semantic state hash.
- `tree`: JSON tree when requested.
- `text`: compact text snapshot.

`generation` must not be used as proof that UI state changed. It can advance
because a caller asked for a new snapshot.

## CLI Changes

Add:

```sh
melatonin-ui -s app capabilities
```

All CLI commands should use one timeout hierarchy:

- endpoint operation timeout.
- CLI child-process/read timeout.
- optional CI test timeout.

The CLI timeout must exceed the endpoint timeout by a fixed buffer so an endpoint
wait can report its own error instead of being killed by the client.

## MCP Changes

Add or expose through `juce_list_sessions`/new `juce_capabilities`:

- protocol version.
- tool feature flags.
- security flags.

MCP tests must use a C++ child-process harness that:

- launches `melatonin-ui mcp`.
- sends `initialize`.
- sends `tools/list`.
- sends `tools/call`.
- supports request timeouts that exceed endpoint timeouts.
- captures stdout/stderr transcripts.
- distinguishes JSON-RPC protocol errors from successful tool calls that return
  endpoint error text.

## Internal C++ Endpoint Changes

Add shared helpers before feature work:

- protocol version constant.
- feature capability registry.
- response/error construction helpers.
- shared MCP tool schema registry used by `melatonin-ui mcp`.
- canonical semantic snapshot serializer.
- non-mutating snapshot serializer for traces.
- state hash generation.
- timeout budget struct.
- security policy struct.
- artifact path validator.

Security policy should include:

- `allowInput`: gates user-like input and semantic user actions.
- `allowMutation`: gates inspector mutation such as bounds/properties.
- `allowFileWrite`: gates endpoint-side writes.
- artifact root: restricts screenshots/traces to an approved directory when file
  output is enabled.

## Fixture Additions

Before adding more feature tests, extract shared test utilities from
`tests/automation_fixture.cpp` into reusable C++ helpers:

- CLI child-process runner.
- MCP child-process JSON-RPC runner.
- JSON parsing/assertion helpers.
- snapshot tree search helpers.
- PNG validation helpers.
- timeout/retry helpers.
- artifact directory helpers.
- failure transcript writer.

Potential location:

```text
tests/automation_test_helpers.h
```

## DemoRunner Scenarios

DemoRunner support should consume this infrastructure rather than introducing a
separate test harness.

Early smoke DemoRunner should validate:

- capabilities.
- snapshot with `stateHash`.
- root screenshot artifact path.
- one CLI command.
- one MCP command.

## Test Matrix

C++ fixture self-test:

- `capabilities` returns protocol version and security flags.
- snapshot returns generation and state hash.
- repeated snapshots can change generation without changing state hash.
- UI mutation changes state hash.
- endpoint timeout is shorter than CLI/MCP process timeout.
- file output is denied when `allowFileWrite=false`.
- artifact-root path traversal is denied.

CLI coverage:

- `capabilities`.
- timeout propagation.
- endpoint error propagation.

MCP coverage:

- `melatonin-ui mcp` starts without an external runtime.
- `initialize`.
- `tools/list` schema validation.
- valid `tools/call`.
- invalid tool name.
- missing required argument.
- endpoint error propagation.
- transcript capture on failure.

## Failure Modes

- `unsupported_protocol`
- `unknown_feature`
- `operation_timeout`
- `file_write_disabled`
- `artifact_path_denied`
- `mcp_process_not_found`
- `mcp_protocol_error`
- `mcp_tool_error`

## Acceptance Criteria

- Feature plans can rely on one response/error shape.
- Snapshot generation and semantic state hash are clearly separated.
- File-writing behavior is gated and testable.
- MCP testing is possible from C++ without Node or a JS test harness.
- Shared C++ test helpers exist before the fixture grows further.

## Evidence Artifacts

- MCP request/response transcript on failure.
- Final snapshot JSON and text on failure.
- Artifact root contents on screenshot/trace failures.
